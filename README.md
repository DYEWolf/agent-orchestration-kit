# agent-orchestration-kit

`@dyewolf/agent-orchestration-kit` is an open-source npm CLI that configures an
existing GitHub repository with an opinionated agent-orchestration workflow for
the external Orca runtime. It installs a reviewed local workflow; it does not
run your work for you or take ownership of your repository.

> **Non-affiliation:** this independent project is not affiliated with,
> endorsed by, or an official product of Orca or its maintainers. “Orca” is
> used only to describe the external runtime compatibility contract.

The canonical public repository is https://github.com/DYEWolf/agent-orchestration-kit.

## Installed V1 files

V1 installs a local workflow with these paths:

- `AGENTS.md` — the CLI-owned Orca constitution managed block; content outside
  the block remains user-owned.
- `.agent-orchestration-kit/config.yaml` — selected profile and generator input.
- `.agent-orchestration-kit/manifest.json` — CLI/bundle versions and hashes for
  the installed files.
- `.agents/THIRD_PARTY_NOTICES.md` — attribution for bundled third-party skills.
- `.agents/skills/<skill>/SKILL.md` — canonical skill bodies, with any pinned
  supporting files, `.agents/skills/<skill>/agents/openai.yaml` discovery
  metadata, and `.agents/skills/<skill>/PROVENANCE.json`.
- `docs/agents/orca-execution.md`, `docs/agents/issue-tracker.md`,
  `docs/agents/skill-overrides.md`, and `docs/agents/domain.md` — canonical
  workflow documentation.

Profiles that select Claude additionally install the Claude discovery paths
`CLAUDE.md` and `.claude/skills/<skill>/SKILL.md`. These are lightweight
wrappers that point Claude Code to the canonical `.agents/skills/` bodies; they
are not installed for codex-only and do not promise behavior outside the V1
compatibility contract.

Generated Markdown files use this exact header:

```markdown
<!-- Generated by @dyewolf/agent-orchestration-kit. V1 does not update this file automatically. -->
```

The managed portion of `AGENTS.md` is surrounded by these exact markers:

```markdown
<!-- agent-orchestration-kit:start version="1" -->
<!-- generated orchestration constitution -->
<!-- agent-orchestration-kit:end -->
```

## Quickstart

Use this in the root of an existing Git repository with a GitHub remote:

```bash
npx @dyewolf/agent-orchestration-kit@latest init
```

`init` first inspects the repository and presents a deterministic ChangePlan.
Review it before confirming. For automation, use `--yes` only when you accept
every local, Orca, and GitHub action enumerated in that plan.

```bash
# Preview without writing files or making external mutations.
npx @dyewolf/agent-orchestration-kit@latest init --dry-run

# Configure a named repository after accepting the complete shown plan.
npx @dyewolf/agent-orchestration-kit@latest init /path/to/repository --yes

# Diagnose an installed workflow or inspect local manifest drift.
npx @dyewolf/agent-orchestration-kit@latest doctor /path/to/repository
npx @dyewolf/agent-orchestration-kit@latest diff /path/to/repository
```

## Prerequisites and ownership

You provide:

- Node.js 22 or newer, Git, and npm/npx;
- an existing Git repository with a GitHub remote and authenticated `gh` for
  that host;
- Orca 1.4.190 or newer on `PATH` (the V1 compatibility baseline), plus Codex;
- Claude Code only for a profile that selects Claude.

V1 supports macOS, Windows, and Linux on Node.js 22, 24, and 26. The CLI checks
the tools, version/capability, runtime readiness, repository registration, and
authentication that its selected profile needs. It never installs tools,
performs login, manages credentials, reads secrets, creates Issues, or creates
Git history/remotes.

## Profiles

Choose a routing profile with `init --profile <name>`; `codex-only` is the
default. Stable means the profile has passed its required live validation.
Pending profiles remain selectable but Doctor reports a routing `WARN` until
their Claude-worker lifecycle validation is complete.

| Profile | Status | Coordinator and worker arrangement | Required tools |
| --- | --- | --- | --- |
| `codex-only` | Stable | Codex coordinates and all bounded worker roles use Codex. | Codex |
| `claude-coordinator` | Stable | Claude Opus coordinates; worker roles use the Codex routes. | Codex, Claude |
| `claude-only` | Pending live validation | Claude Opus coordinates and reviews; Claude Sonnet explores and implements. | Claude |
| `codex-coordinator` | Pending live validation | Codex coordinates; Claude Sonnet explores and implements, and Claude Opus handles difficult/judgment/review roles. | Codex, Claude |

Codex routes use the exact configured model and effort level. Claude routes use
the moving `sonnet` and `opus` aliases with effort intentionally unset, so
Claude Code uses the resolved model default; Doctor checks the installed Claude
capability instead of treating a single effort value as universal.

The installed workflow has one coordinator who owns the conversation, GitHub
Issue, Orca Run, task graph, gates, and integration. Workers receive bounded
Tasks, do not create nested workers, Runs, Tasks, worktrees, or branches, and
send one `worker_done` report. An implementation Issue has one issue-owned Run;
reviewers return `SHIP`, `FIX_FIRST`, or `RETHINK` without implementing a fix.

## Commands

V1 exposes exactly these commands:

```text
agent-orchestration-kit init [options] [path]
agent-orchestration-kit doctor [options] [path]
agent-orchestration-kit diff [options] [path]
```

`init [path]` defaults to the current directory and `codex-only`. Its options
are:

| Option | Effect |
| --- | --- |
| `--profile <profile>` | Select `codex-only`, `claude-coordinator`, `claude-only`, or `codex-coordinator`. |
| `--dry-run` | Render and print the ChangePlan without writing or executing planned actions. |
| `--yes` | Accept exactly the complete, enumerated ChangePlan, including its Orca and GitHub actions. |
| `--no-global` | Suppress the offered global Orca skill installation. |
| `--no-orca-registration` | Suppress the offered Orca repository registration. |
| `--no-github-mutations` | Suppress GitHub label creation. Doctor will retain actionable label failures. |
| `--json` | Emit stable machine-readable JSON. With a non-dry-run `init`, it requires `--yes` because interactive output would corrupt JSON. |

`doctor [path] [--json]` reports `PASS`, `WARN`, `FAIL`, or `SKIP` for the
repository/remote, `gh` authentication, canonical configuration, Orca
compatibility/readiness/global skill/repository registration, selected harness,
local artifacts and attribution, managed-block and manifest integrity, required
GitHub label, and routing compatibility. `diff [path] [--json]` is read-only
and reports modified or missing manifest-owned files and managed-block changes.

## What init changes

Every `init` begins with a deterministic ChangePlan: planned file creates or
managed-block updates, collisions and drift, available or suppressed external
actions, GitHub label actions, validations, and rollback actions. The plan is
shown for confirmation unless `--dry-run` or `--yes` is supplied. It may offer,
but never silently performs, installation of the official global Orca
orchestration skill, repository registration, and creation of the missing
`ready-for-agent` GitHub label. Those actions are independently suppressible by
the options above; the CLI neither installs prerequisites nor manages their
credentials.

Local files are written atomically. If a required local write or verification
fails, V1 restores replaced files and removes files and empty directories it
created. Local installation completes before any approved global or remote
action; a later external failure does not roll back an already-consistent local
installation.

The CLI owns only its managed block in `AGENTS.md`; content outside that block
is preserved byte-for-byte. A repeated install of the same version with no
drift is a verified no-op. If a manifest-owned file or managed block has drift,
V1 reports it and refuses to overwrite it—there is no force flag. If an
installation was made by a different version, V1 stops: updates,
reconfiguration, profile transitions, and ejection are outside V1.

## Troubleshooting

- **A prerequisite is missing:** install or authenticate the reported tool
  yourself, then rerun `doctor`. `init` does not install tools or log in.
- **Orca fails compatibility or readiness:** confirm Orca is on `PATH`, meets
  the 1.4.190 baseline, and exposes the required machine-readable capabilities;
  Doctor names the failed check. Use `--no-global` or
  `--no-orca-registration` only when you intentionally want those actions
  suppressed.
- **Global skill or repository registration is absent:** accept the specific
  offered ChangePlan action, or perform the prerequisite yourself and rerun
  Doctor.
- **GitHub authentication, repository identity, or `ready-for-agent` label
  fails:** authenticate `gh` for the repository host. Accept the planned label
  creation when the label is missing; existing label metadata drift is reported
  without modification. `--no-github-mutations` intentionally leaves the
  resulting Doctor failure actionable.
- **A managed-file collision or drift is reported:** inspect the plan or
  `diff`; preserve or manually reconcile the user-owned change. V1 has no
  overwrite, update, or eject mode.
- **A pending profile reports `WARN`:** it is selectable, but its live
  Claude-worker validation has not yet passed. Use a stable profile when that
  warning is unacceptable.
